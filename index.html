Smart-Route Emergency Department:
Optimizing Total Time to Treatment (TTT)

An end-to-end data pipeline and dynamic routing platform that balances live Singapore hospital A&E waiting queues, precipitation delays, and 60-day historical dengue outbreak vectors to save up to 2.5 hours per emergency trip.

github.com/ttan-ttan/hospital_wait_time Google Drive Project Folder
Plain English Explanation for Non-Technical Stakeholders:

When someone gets sick, taking them to the nearest hospital isn't always the fastest way to get care. If the nearest hospital is overcrowded with a 3-hour wait, driving 10 minutes further to a quieter hospital gets the patient seen by a doctor much sooner. Smart-Route ED continuously checks live hospital queue times and weather to recommend the fastest total trip.

Core Engineering Objectives

Scope & Vision
1

Automated Data Collection

Scrape and ingest live hospital queue times from public portals (SingHealth, NHG, NUHS) every 15 minutes, alongside real-time weather readings.

Plain English: Never rely on old or manual spreadsheets.
2

Geographic Standardizing

Convert mismatched postal addresses, lat/long coordinates, and region names into Singapore's 28 Postal Sectors (D01 to D28).

Plain English: Make all government data talk in the same language.
3

Epidemiological Analysis

Test whether 60-day historical rainfall patterns correlate with dengue outbreak clusters and subsequent A&E queue spikes using SQL window functions.

Plain English: Predict future hospital crowding before it happens.

Spatial Harmonization (D01–D28)

Two Incompatible Keys Resolved
The Challenge: Dengue reports use locality text (e.g. "Springleaf / Lentor"), hospital dashboards use 6-digit postal codes (e.g. 119260), and weather stations use Lat/Long coordinates. We resolved two incompatible geographic keys by mapping the first 2 digits of 6-digit postal codes to standard Singapore Postal Sectors (D01–D28).

Data Validation & Pipeline Quality Gates

Failure Handling
Validation Check Pipeline Stage / Location Behaviour on Failure / Error Handling
HTTP status and API result code All extractors Logs the error and returns empty data frame; pipeline execution continues safely.
Network timeout (10–120s) All extractors Caught gracefully, logged per date or per call without crashing orchestrator.
Element-presence wait (10s) Selenium scrapers Timeout is caught; that specific unresponsive hospital is omitted from the batch.
Postal-code format (6 numeric digits) CLI input handler Rejected with a clear error message before any database query runs.
Numeric coercion with null-fill All transformations Bad string values become 0 or NaN; valid row context is safely retained.
Exact-duplicate removal Dengue transformation Duplicate snapshot row dropped; count logged in pipeline summary.
Uniqueness constraints PostgreSQL DDL Database insert rejected on repeat load to prevent duplicate primary records.
Unit tests suite test/ modules Tests any failure across extract (`test_extract.py`), transform (`test_transform.py`), and loader (`test_loader.py`).

Deliverables Hub
Primary Goal: VALIDATED

Dynamic Routing Saves 2.5 Hours

Routing ambulances to TTSH (44 min wait) instead of NUH (180 min wait) during queue spikes effectively slashes total emergency time-to-treatment.

Secondary Lag Hypothesis: INCONCLUSIVE

60-Day Runway Required Expansion

60-day weather data was too short to establish direct causality with A&E queue spikes due to low rainfall in that window; >180 days across monsoon cycles is recommended.
